## 1. Что это за проект

Система из **двух Telegram-ботов** для компании ОСК (Бишкек, проверка новостроек):

1. **@OSK_Tech_bot** — внутренний бот для **сотрудников**. Выездная проверка
   застройщика по пунктам: техническая и юридическая части. Итог — баллы/проценты,
   PDF-отчёт, фото и строки рейтинга уходят в Google.
2. **@OtzyvSK_bot** (имя «ЮР заключение ОСК») — **публичный** бот для **покупателей**.
   Любой человек фотографирует документы застройщика, получает понятное заключение
   (процент заполненности + риски), а данные копятся у администратора.

Оба бота — один и тот же код, режим выбирается переменной `PUBLIC_MODE`. Данные
обоих складываются в одну Google-таблицу (разные листы) и одну папку на Диске
(по компании/объекту), чтобы потом можно было **сравнивать**.

### Переменные окружения

| Переменная | Где | Назначение |
|---|---|---|
| `BOT_TOKEN` | оба env | токен бота от @BotFather |
| `ADMIN_IDS` | osk-bot.env | Telegram ID админов через запятую (сейчас `930419117`) |
| `PUBLIC_MODE` | osk-bot-public.env | `1` → публичный режим покупателя |
| `APPS_SCRIPT_URL` | оба | URL веб-приложения Apps Script (`.../exec`) |
| `APPS_SCRIPT_SECRET` | оба | пароль, совпадает с `SECRET` в Code.gs |
| `SUPPORT_CONTACT` | osk-bot-public.env | ссылка «Связаться» (WhatsApp), необязательно |
| `DATA_DIR` | оба | папка базы SQLite |

⚠️ **Токены разных ботов легко перепутать.** @OSK_Tech_bot имеет id `5273935935`
(начало токена). Токен @OtzyvSK_bot начинается с ДРУГИХ цифр. Проверка, чей токен:
`curl -s "https://api.telegram.org/bot$(cat ФАЙЛ)/getMe" | grep -o '"username":"[^"]*"'`.

### Если @OtzyvSK_bot отвечает «Администратор бота ещё не настроен»
Эта фраза есть только в режиме **сотрудников** и выдаётся, когда `ADMIN_IDS` пуст.
Значит, токен @OtzyvSK_bot обслуживает процесс в режиме сотрудников без админов:
служба `osk-bot-public` на старом коде (без `PUBLIC_MODE`), в её настройках нет
`PUBLIC_MODE=1`, или бот с этим токеном запущен где-то ещё вручную.
- Кто и в каком режиме запущен: `sudo journalctl -u osk-bot-public | grep "запущен:"` —
  должно быть «Публичный бот для покупателей запущен: @OtzyvSK_bot».
- Лишние копии: `pgrep -af doc_bot.py` (должно быть ровно две — по одной на службу);
  в логе `Conflict` = с этим токеном работает ещё кто-то.
- Лечение: заново запустить `install-public.sh` — он сам обновляет код, проверяет
  токен (getMe, не токен @OSK_Tech_bot) и подтверждает публичный режим по логу.

## 4. Бот сотрудников @OSK_Tech_bot

- **Доступ** только по списку: сотрудник пишет `/start` → «🔑 Запросить доступ»,
  админу приходит кнопка «Разрешить/Отклонить». Управление — команда `/staff`.
  Админ определяется по `ADMIN_IDS`. При первом входе бот спрашивает ФИО (для отчётов).
- При `/start` — выбор раздела: **⚖️ Юридическая** или **🔧 Техническая**.
  Это **две независимые проверки** по объекту.
- Ход: ввод компании и ЖК (есть подсказки из прошлых завершённых проверок) →
  карточки пунктов. На каждом: фото (можно несколько/PDF), отметки, комментарий
  текстом, «🚫 Отсутствует», навигация, «📑 Пункты», «🏁 Завершить».
- **Техническая часть** — галочки складываются, итог из **38 баллов**. Оценка:
  30+ «Хорошо», 20+ «Удовлетворительно», иначе «Неудовлетворительно».
- **Юридическая часть** — на пункте выбирается ОДИН вариант (взаимоисключающие
  кнопки), итог в **процентах из 176**. Оценка: 75%+ «Хорошо», 50%+ «Удовл.».
- **Завершение**: PDF-отчёт в чат (фото сжаты, чтобы влезть в лимит Telegram) +
  сохранение в Google: фото в папку, строка в лист рейтинга.
- **«📋 Мои проверки»** — сотрудник видит только свои, по нажатию бот **пересобирает
  и шлёт PDF в чат** (Диск им не нужен). **«🗂 Проверки всех менеджеров»**,
  **«📊 Таблица рейтинга»**, **«👥 Сотрудники»** — только у админа.
- **🗑 Удаление** проверки (своей — автор, любой — админ): убирает из списков,
  подсказок и фото с Диска.
- **`/sync <id>`** (админ) — досохранить завершённую проверку в Google (например,
  если не сохранилась из-за сбоя). Пишет в те же листы.

### Куда сохраняется (сотрудники)

- Папка Диска: `Тех РЕЙТИНГ / Компания / ЖК / «Техническая ДАТА»` (или «Юридическая ДАТА»).
- Листы таблицы: техническая → **«Рейтинг»** и **«Детали»**; юридическая →
  **«Рейтинг — Юр»** и **«Детали — Юр»**. (Так уже лежат данные — не переименовывать.)

## 5. Публичный бот @OtzyvSK_bot (покупатели)

- **Открытый доступ**, без списка сотрудников. `/start` → приветствие → «Новая проверка».
- Ход: ввод компании → ЖК → **8 документов** по очереди. На каждом короткая
  инструкция (что именно снимать) + при наличии фото-образец из `buyer_examples/`.
  Фото прислал → документ зачтён; «🚫 Нет / не дали» → пропуск.
- **Заключение** (простым языком): процент заполненности, что есть, чего не хватает
  (как **риск** — по каждому недостающему объяснение), честная оговорка «наличие —
  хорошо, но содержание ещё проверяем».
- **При 90%+** — предложение: проверка документов, консультация, заключение и
  **сопровождение до госрегистра со скидкой 50%**; бот просит имя и телефон.
- Данные → лист **«Покупатели»** в той же таблице + фото в папку
  `Тех РЕЙТИНГ / Компания / ЖК / «Покупатель ДАТА»` (та же компания/ЖК, что у
  сотрудников → группируется для сравнения).

### 8 документов и что снимать (из `osk_bot/buyer.py`)

1. **Статус земельного участка** — госакт (красная/зелёная книга). Внутренние
   страницы: собственник, ид. номер участка, назначение, таблицы «Сделки» и
   «Ограничение права» (аресты). Обложку с гербом — не нужно.
2. **ГЗ / АГЗ** — первый лист (жёлтый, № и адрес) + последний лист (печать, красная
   ленточка). Плюс страницы с параметрами участка.
3. **ИТУ / ТУ** — титул (№, объект), опись сетей, и по каждой сети лист с
   мощностью/объёмом и печатью (электричество, вода, канализация, газ).
4. **Выписка из ЕГРПНИ** — весь лист: собственник, ид. код, раздел «Обременения
   (ограничения)». Важна свежесть (дата вверху).
5. **Заключение госэкспертизы** — первый лист (реестр №, объект, печать «УТВЕРЖДАЮ»)
   + последний лист (раздел VII, вывод «соответствуют…», подписи, печать, ленточка).
6. **Лицензия** — сама лицензия (серия/№, компания, «строительно-монтажные работы»,
   уровень) + приложение с перечнем работ.
7. **Реестр строящихся объектов** — весь лист подтверждения: объект, №, основание
   (экспертиза, АГЗ), заказчик/подрядчик, этажность/площадь, печать инспектора.
8. **Договор (ДДУ/ПДКП)** — титул (название, №, дата), квартира (блок/этаж/№, площадь),
   цена и порядок оплаты, срок сдачи, последняя страница с подписями.

Баллов у покупателя нет — считается только наличие фото (процент = сколько из 8).
Порог предложения — 90% (`OFFER_THRESHOLD` в `buyer.py`).

## 8. Как продолжать

- Поменять пункты/баллы сотрудников → `osk_bot/checklist.py` (ключи не менять).
- Поменять документы/инструкции/заключение покупателя → `osk_bot/buyer.py`.
- Любая правка кода → `git push` в ветку, затем на сервере команда установки
  (основная перезапускает обе службы; публичную можно отдельно `restart`).
- Тесты офлайн (фейковый Telegram+Google) лежали в скретчпаде сессии: сквозные
  сценарии сотрудника и покупателя — при больших правках прогонять аналогично.
- Всегда проверять, какой токен в файле (`getMe`), прежде чем запускать —
  это главный источник ошибок при деплое.

Атрибуция коммитов — как в текущей ветке (`Co-Authored-By: Claude …`).
